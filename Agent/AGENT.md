AGENTS.md
1. General Guidelines
This is a Web Application project.

Your primary responsibility is developing and maintaining the UI/UX and frontend code. You may also work on backend functionality when required by the assigned task.

Write clean, maintainable, reusable, and consistent code.

2. Before Starting Any Task
Read the following project documentation:

agent/rules.md — Development rules and coding conventions.
agent/project.md — Project overview, goals, and requirements.
agent/structure.md — Project file structure and installed libraries.
agent/styles.md — UI/UX design system and visual guidelines.
Read only the additional source files relevant to your assigned task. Avoid scanning the entire project unless necessary.

3. Development Guidelines
Understand the existing code before modifying it.
Follow the established project structure and conventions.
Reuse existing components, functions, utilities, and libraries whenever possible.
Avoid unnecessary files, duplicated components, and redundant code.
Keep changes focused on the assigned task.
Do not modify unrelated features or files.
Preserve existing functionality unless the task requires changing it.
Do not overwrite or revert changes made by other agents.
4. Package and Library Management
You are allowed to install new libraries when they are genuinely needed.

Before installing any package:

Inspect package.json to check whether the package is already installed.
Check whether an existing package can provide the required functionality.
Avoid installing libraries that duplicate existing functionality.
If the required package already exists, use the installed version without upgrading it unnecessarily.
When installing a new package:

Choose a stable version compatible with the existing project.
Use the project's existing package manager.
Avoid unnecessary dependencies.
Do not upgrade or replace unrelated packages.
Ensure package.json and the corresponding lockfile are updated correctly.
5. Project Structure and Documentation
Keep agent/structure.md synchronized with the actual project.

Whenever you add, remove, rename, or move files or folders:

Update the corresponding structure entry.
Add a short description of each new file or folder.
Remove outdated entries.
Documentation must always reflect the actual project, not an intended or outdated structure.

6. UI/UX Guidelines
Follow agent/styles.md when creating or modifying UI.
Maintain visual consistency across all pages and components.
Prefer reusable components for shared UI elements.
Ensure responsive layouts for different screen sizes.
Consider usability, accessibility, and clear user interactions.
Do not introduce arbitrary design changes outside the task scope.
7. Task Completion
After completing a task:

Summarize the implemented changes.
List the important files created, modified, or removed.
Mention any packages installed, removed, or changed.
Confirm that relevant documentation has been updated.
Report any remaining issues or decisions that require the user's attention.
8. General Principles
Follow the assigned task and its requirements.
Prefer simple solutions over unnecessary complexity.
Do not make assumptions when requirements are unclear.
Ask for clarification before making significant architectural or destructive changes.
Keep the project consistent, organized, and easy for other agents and developers to undndersta.
